## 1. V24.01 Client `.fsdbinary` C-Extension Loader (`tools/sde-import/cfsd_runner.c`) — **RESOLVED (`plan:D-1`, `plan:D-2` DONE)**

- **Context (`D-1` / `D-2`):** EVE Online V24.01 (`build 3619879` / `3624425`) stores its `.fsdbinary` static data archives (`res:/staticdata/*.fsdbinary`) in CCP's binary FSD format, whose schema and offset-table decoders are compiled into per-archive native Python 2.7 C-extension shared objects (`cfsd*Loader.so`) inside `~/Library/Application Support/EVE Online/SharedCache/tq/EVE.app/Contents/Resources/build/bin64/`.
- **How `tools/sde-import` runs against a local client install:** [`tools/sde-import/cfsd_runner.c`](../tools/sde-import/cfsd_runner.c) is a C host binary linked against the V24.01 client's embedded `libpython2.7.dylib` that initializes the client Python 2.7 interpreter so [`tools/sde-import/import_sde.py`](../tools/sde-import/import_sde.py) can invoke each archive's `Loader.load()` directly and populate the full local SQLite database (`data/evomu_sde.sqlite`, `213/213` resources across `42` tables) and [`data/sde_import_manifest.json`](../data/sde_import_manifest.json).
- **Runtime & Test Resolution (`D-2`):** [`SdeRegistry::default_db_path()`](../crates/eve-sde/src/lib.rs) and [`SdeRegistry::with_canonical_seed()`](../crates/eve-sde/src/lib.rs) resolve strictly to `data/evomu_sde.sqlite` (or `EVOMU_SDE_PATH`), failing loudly with [`SdeError::MissingDatabase`](../crates/eve-sde/src/lib.rs) when the local SDE database has not been built via `tools/sde-import`.

## 3. Real-Client Handshake Encryption (`plan:T-6` OPEN, `plan:P-6` DONE)

- **How the client is pointed at EvoMu (no client files changed):** `EVE.app/Contents/MacOS/EVE /server:127.0.0.1 /port:<macho_port> /login:<user>:<password>`. `utillib.GetServerName`/`GetServerPort` read `/server:`/`/port:`, and `connection.TryAutomaticLogin` uses `/login:` once `machoNet.GetServerStatus` reports OK. [`tools/client-harness/run_journeys`](../tools/client-harness/run_journeys) (`--launch-real-client`) does this and kills the client process group and `eve_crashmon` afterwards.
- **Blocker for stock `EVE.app` (`journey:*` / `plan:T-6`):** The installed client's `start.ini` sets `cryptoPack = CryptoAPI`, so `evecrypto.cryptoapi` encrypts the handshake session key with CCP's embedded RSA public key (`blue.crypto.GetSharedAsymmetricCipher`) and verifies the server's handshake function with it. After `"OK CC"` every handshake frame is AES-encrypted with a key only CCP's private key can recover, so no third-party server can read the login request. EvoMu implements the `Placebo` crypto pack (`plan:P-6` `DONE`).
- **Working local procedure (scratch only, `SharedCache` untouched):** Copy the client `build/` directory byte-for-byte into a plain directory, add `common.ini` with `[main]` / `cryptoPack = Placebo` (`eveprefs.Init` merges `common.ini` over `start.ini`; this is the same client setting `evemu_Crucible` requires), and run that copy's `bin64/exefile /server:127.0.0.1 /port:<macho_port> /login:<user>:<password>` with the copy as working directory. Adding the file inside an `.app` copy breaks its code-signature seal (Gatekeeper refuses it), and symlinked copies fail the client's manifest/executable-path verification.
- **Status:** Dual-client bridge verification (`--bridge-harness-test`, `plan:T-7` `DONE`) passes across all 10 core bridge journeys, while `journeys[<id>]["passed"]` (`plan:T-6`, `29` `journey:*` rows) remains `False` until end-to-end execution against the Placebo-staged real client is wired and executed.

## 4. Machines Without Local Client Data (macOS or Windows)

- **Context:** EvoMu supports macOS and Windows, and the gates (pre-flight, `run_review.py`, `final_gate.py`) run locally on whichever machine is in use (`AGENTS.md`, "Supported platforms"). Local SQLite files (`data/evomu_sde.sqlite`, `data/quasar_descriptors.sqlite`) are not committed (§2).
- **Rule:** On a machine missing local client data files, tests that read them fail with a panic naming the missing file or client path. Such failures are acceptable in a claims review only when each panic names a missing local-only file; `final_gate.py` must run on a machine that has all local data.
